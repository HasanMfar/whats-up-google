How this works

HasanMfar/whats-up-google

Each config gets its own temporary Xray process and its own local SOCKS port. Real requests go through that node to Google, and the response decides the verdict. Nothing is trusted, nothing is sampled.

What runs where

Task In this page Local bridge
Decode subscriptions, parse links, dedupe yes yes
Inspect every field of a config yes yes
Pick and export subscriptions yes yes
Read a CLI scan report yes yes
Open a tunnel and send probes no yes
Run the Xray core no yes

Why the browser cannot run Xray: a tab has no raw TCP or UDP sockets, no SOCKS listener, and no way to start a native binary. Xray needs all three, so the probing half stays on your machine — and the page drives it over loopback.

Verdicts

  • Clean Every check passed; Google does not flag this node.
  • Flagged At least one check hit a block: captcha, region block, or the API location error.
  • Dead No HTTP response got through the node at all.
  • Error The node answered, but a probe errored. Re-run to confirm.

How a block is detected

  • search Redirected to /sorry, or an unusual-traffic marker.
  • gemini 403/429, the country-block page, or /unsupported.
  • gemini_api "User location is not supported for the API use" means blocked. Any other API error means the location is accepted.
  • antigravity 403/429 or a block page.

Diagnostic tool for your own configs. It is not a proxy and provides no circumvention of its own — every request goes through a config you already have.
